# 2026-11-14 · TP=2 失效：LoRA 加载失败 与 出片全噪

> 本次更新只涉及一条故障线：TP2 接入 LoRA 后「失效」。结论是两条独立问题叠加，
> 不是「TP2 不支持 LoRA」。

## 一句话结论

| 顺序 | 症状 | 归属 | 处置 |
|---|---|---|---|
| A | LoRA 加载失败，且不报错中断 | `T8-convert` 的 adaln 与 curve 底模形态不匹配 | 换 DMD / ema / Combat |
| B | 加载成功，但成片全是噪点 | `custom_nodes` 残留插件副本，切分被执行两次 | 移出备份 + patch 加幂等标记 |

## 时间线

1. 生产工作流带 `T8-convert` → `shape '[96768, 8]' is invalid`，50 个 adaln 键被上游 `except` 静默丢弃；
2. 换 DMD + Combat → 出片纯噪声，第一反应是「Combat 维度不匹配」；
3. TP2 不挂任何 LoRA、20 步复跑 → 仍然噪声，排除 LoRA；
4. 日志显示同一次加载切了两遍 → `custom_nodes` 下有插件备份目录被一并加载；
5. 移出备份 + 两处 patch 加幂等标记 → 单卡/TP2、有/无 LoRA 全部复验通过。

## 症状 A：LoRA 加载失败（静默）

```
shape '[96768, 8]' is invalid for input of size 260112384
ERROR {name} diffusion_model.blocks.0.adaln_proj.linear.weight
```

- `T8-convert` 的 adaln 按 **2688 维全量底模** 训练（`lora_A [16, 2688]`）；
- `ref2va / hybrid int8` 底模是 **curve 形态**（`adaln_t_table [1025, 8]`、`adaln_proj.weight [96768, 8]`）；
- `B@A` 得到 `[96768, 2688]`，reshape 不成 `[96768, 8]`；
- 上游 `comfy/weight_adapter/lora.py` 用 `try/except` 包住，只打一条 error 就继续，
  **界面仍显示加载成功**，该 LoRA 实际未生效。

形状体检（按底模权重键逐一对齐）：

| LoRA | 键数 | `ref2va int8` | `hybrid int8` |
|---|---|---|---|
| `ema_pruned_comfyui` | 417 | 全匹配 | 全匹配 |
| `H3_Combat_V2` | 417 | 全匹配 | 全匹配 |
| DMD `8step_turbo_pruned` | 829 | 全匹配（adaln 8 维 curve） | 全匹配 |
| `T8-convert` | 208 | 50 个 adaln 键不匹配 | 同样不匹配 |

> **形状对齐只说明「不会报错」，不等于「能用」。** `Combat` 是面向 hybrid 运动分支训练的，
> 打在 pruned 权重上形状能过、语义不对，画面会崩——此前那版噪声就是这么来的。
> 2D 版只用 `ema_pruned turbo`；要用 Combat 做动作增强，必须换 hybrid 底模，
> 而 hybrid 单卡 1344×768 约 700 s/it，只适合小分辨率验证。
>
> 不要用「跳过形状检查」去硬打补丁：那会把错维度的 delta 塞进权重，比丢弃更糟。

## 两个必须注意的点

1. **不要把「补丁能跑通」当成「LoRA 生效」**。把 LoRA 转 patch 并绕过维度校验，只会让不匹配的
   delta 被强行写入；`Combat` 打在 pruned 权重上就是这种情况，画面直接崩。
2. **Combat 只在 hybrid 底模上有效**。它增强的是 hybrid 的运动分支，pruned 底模没有对应结构；
   若要使用，代价是单卡 1344×768 约 700 s/it，只适合小分辨率。2D 生产固定用 `ema_pruned turbo`。

## 症状 B：换匹配 LoRA 后仍是纯噪声

- 同 seed、同工作流：8188 单卡正常，8191/8192 抽帧为静态噪点；
- 换 `ema_pruned`、甚至完全不挂 LoRA 依然噪声 → 与 LoRA 无关；
- 两个 rank 成片 md5 一致 → 两卡同步，但同步的是同一份错误结果。

日志（同一次加载出现两行）：

```
[tp2] rank0 state_dict split: heads 56->28, keys 932
[tp2] rank0 state_dict split: heads 28->14, keys 932   ← 第二次
```

`custom_nodes/` 下除 `comfyui-tp2` 外还有 `comfyui-tp2.bak-377line-11071942`，
ComfyUI 会把两个目录都当插件导入，两个模块各自 monkeypatch 一次，切分叠加。
qkv 头数只剩应有的 1/4，注意力彻底错位。

## 修复清单

| 文件 | 改动 |
|---|---|
| `comfyui-tp2/__init__.py` | `load_diffusion_model_state_dict` / `load_lora_for_models` 加 `comfy.sd._tp2_*_patched` 幂等标记 |
| `scripts/bench.py` | 支持 `--lora ""` 真无 LoRA；补齐 `--lora2`、FFN/head 分块、轮询超时容错 |
| 运行环境 | 插件备份移出 `custom_nodes`（`/home/jay/tp2/backups/`） |

## 复验矩阵（832×480 / 56 帧 / 8 步 / seed 145）

| 配置 | 修复前 | 修复后 |
|---|---|---|
| 单卡 + `ema_pruned` | 正常 | 正常 |
| 单卡 + DMD + Combat | 正常 | 正常 |
| TP2 + `ema_pruned` | 纯噪声 | **正常** |
| TP2 + DMD（不带 Combat） | 纯噪声 | **正常** |
| TP2 + DMD + Combat | 纯噪声 | 仅形状通过；**画质未验收，不建议在 pruned 上使用** |
| TP2 无 LoRA（20 步） | 纯噪声 | — |

修复后：`heads 56->28` 仅一次、`lora split keys=208/416`（DMD 为 208/828），
per_step 3.47 s（双重切分时 3.98 s），显存峰值 12.0–13.7 GB/卡。

## 判定口径（三条命令）

```bash
grep 'state_dict split' r0.log     # 只应出现一次 heads 56->28
grep 'lora split keys'  r0.log     # 单 LoRA 208/416；DMD 208/828；各一次
ls custom_nodes | grep -i tp2     # 只应有一个条目
```

另需检查 `ERROR ... lora key not loaded` 的条数——为 0 才说明 LoRA 真的全量生效。

## 遗留

- 32B 文本编码器仍在 CPU 上跑（单进程约 25.9 GB 内存），是当前最大的固定开销；
- `T8-convert` 若必须使用，需要全量非剪枝底模的 time_embedder 做 8 维曲线投影，代价大于换 LoRA；
- 建议把「插件目录只允许一个副本」写进部署检查清单。
